[5 points]  Analysis:
Insight: With the bimodal  predictor  (n=0:  no  global  history),  a  given
static branch is predicted using only  a  single  2-bit  counter.  With  the
addition  of  global  history,  that  single  counter  is   specialized   or
multiplied into many more counters. All these counters are used by the  same
static branch for more specialized predictions among its dynamic  instances,
promising higher accuracy as long as there are adequate  counters  available
in the  table  (not  just  for  this  static  branch,  but  for  all  static
branches). Thus, with the addition of global history, there is  a  need  for
more 2-bit counters … the key  idea  being  that,  at  some  point,  bimodal
cannot even take advantage of more counters (see your analysis  section  for
bimodal, above) whereas gshare can. Summarizing: Gshare needs  an  abundance
of counters and, unlike  bimodal,  it  can  exploit  abundant  counters  for
higher accuracy.
